## Unit Testing With Injection

`P4Client` is designed to be testable without shelling out to a real Perforce server on every test run.

You can inject:

- `executor` to stub command execution
- `env`, `cwd`, and `hostName` to pin process-dependent behavior

```ts
import { P4Client } from "p4client-ts";

const p4 = new P4Client({
  hostName: "build-host",
  executor: async () => ({
    command: "p4",
    args: ["info"],
    stdout: "Client host: build-host\nUser name: p4ts-e2e\n",
    stderr: "",
    exitCode: 0
  })
});

const environment = await p4.getEnvironment();
```

## End-to-End Tests

This repository includes `packages/test-stream`, which contains the canonical stream seed used by the E2E harness. Run the canonical E2E command from the repository root:

```bash
bun run test:e2e
```

The runner downloads or reuses hash-verified Perforce `p4`/`p4d` binaries, creates a disposable localhost server and workspace, provisions the stream, seeds the fixture, runs all E2E scenarios, and cleans up. The first run requires network access.

Use the [API Reference](/api/) for exact shapes while building tests around the client.
