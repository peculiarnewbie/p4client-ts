---
title: Testing and Fixtures
description: Mock the P4 service or replay strict captured CLI output.
---

Use Bun's test runner. Service mocks exercise application logic without starting
Perforce; replay layers exercise command construction and wire decoding.

### Mock operations

```ts
import { Effect } from 'effect';
import { P4 } from 'p4client-ts';
import { layerTest } from 'p4client-ts/testing';

const program = Effect.gen(function* () {
  const p4 = yield* P4;
  return yield* p4.listOpenedFiles({});
});
const result = await Effect.runPromise(program.pipe(Effect.provide(layerTest({
  listOpenedFiles: () => Effect.succeed({ items: [], messages: [] }),
}))));
```

Unspecified methods fail as defects naming the unexpected operation. A mocked
watch emits a single `done` event by default; provide `watch` overrides to test
items, messages, failures or progress.

### Strict replay

```ts
import { Layer } from 'effect';
import { configLayer } from 'p4client-ts';
import { readWireFixture, replayExecutor } from 'p4client-ts/testing';

const fixture = readWireFixture('./tests/fixtures/opened-empty.json');
const replayLayer = P4.layer.pipe(Layer.provideMerge(Layer.merge(
  configLayer({}),
  replayExecutor([fixture], { chunkSize: 7 }),
)));
const replayed = await Effect.runPromise(program.pipe(Effect.provide(replayLayer)));
```

Replay compares normalized argv, including subcommand flags and stdin, and
reports the nearest fixture on a miss. Only global connection/program flags
are stripped. Use individual fixtures when several captures share argv
(for example successful, stopped-server and timeout `info`).

For Promise tests, use `createP4ClientFromLayer(replayLayer, derive, config)`
from `p4client-ts/promise`, where `derive` rebuilds the layer for new configuration.
Dispose the client in `finally`. A `P4`-only mock supports neutral methods;
Node helpers need exposed `P4Config` and `P4Executor`.

### Recording and live tests

`recordingExecutor(executor)` returns an executor layer and recorded invocations.
`scriptedExecutor` responds to invocations with synthetic stdout/stderr/exit
data. Use Effect Schema for runtime validation; use strict replays for real
Perforce protocol behavior.

From the repository root:

```sh
bun run typecheck
bun run test
bun run test:e2e
bun run docs:check
bun run build
bun run pack:core
```

The e2e runner starts a disposable localhost p4d, seeds a stream and workspace,
and cleans up afterward. The harness checks the explicit `-p` against that
isolated port and permits `-x -` only immediately before `print`.

To refresh wire captures, run `bun run wire:capture`, then
`bun run --cwd packages/core wire:reasons`. Review the golden reason diff.
Every capture must be referenced by a test; the evidence-only allowlist may
only shrink. Chunk-split tests cover both JSON and Python marshal input.


### Complete Promise replay client

Build `derive` from the same library-compatible Effect installation; it must expose
config and executor for Node helpers. A frozen facade has no prototype to patch.
A consumer that uses an incompatible Effect version can test its own client-factory
boundary, or keep this replay inside an isolated stable-Effect adapter.

```ts
import { createP4ClientFromLayer } from 'p4client-ts/promise';
import type { P4ClientOptions } from 'p4client-ts';

const derive = (options: P4ClientOptions) => P4.layer.pipe(Layer.provideMerge(Layer.merge(
  configLayer(options), replayExecutor([fixture]),
)));
const promiseClient = createP4ClientFromLayer(derive({}), derive);
try {
  const replayedOpened = await promiseClient.listOpenedFiles({});
  console.log(replayedOpened.items, replayedOpened.messages);
} finally { await promiseClient.dispose(); }
```

Each derived client owns a runtime too. For request scope, `withP4Client` disposes
on both success and rejection:

```ts
import { withP4Client } from 'p4client-ts/promise';

const scopedOpened = await withP4Client({
  connection: { port: 'ssl:perforce:1666', user: 'alice', client: 'alice_ws' },
}, (scoped) => scoped.listOpenedFiles({}));
```

The callback owns clients it derives with `with`; dispose those separately. An app
Effect adapter can use acquire/release around the Promise client and forward its
interruption through AbortSignal. Do not pass incompatible app schemas or layers
through this boundary; validate untyped `runTagged` rows on the app side instead.
